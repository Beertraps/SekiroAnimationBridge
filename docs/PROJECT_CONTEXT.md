# Current update: 0.7.0 — control rig (retarget add-on 0.3.0)

- User asked for something that makes imported rigs nicer to animate (they only have point-like bones). Of the options presented they chose an **Add control rig** button in the add-on: FK controls, IK arms and legs with an IK/FK switch, and the current animation baked onto the controls. Foot roll, finger IK and face controls were left out of the first version.
- blender_addon/sekiro_retarget/control_rig.py works in the same armature. Each game bone gets COPY_TRANSFORMS "Control rig FK" from MCH-FK-<bone>, a copy of the game edit bone parented to FK-<bone>; IK-driven bones get a second COPY_TRANSFORMS "Control rig IK" from MCH-IKS-<bone> on the IK chain, whose influence is an AVERAGE driver on pose.bones["IK-<end>"]["ik_fk"]. Game rest matrices never change (mesh binding, weapon sockets, the importer's reference pose and the exporter keep working). New bones have use_deform off and carry 'sekiro_control' (kind) and 'sekiro_control_for' (JSON list of driven game bones, read by the exporter). The layout is JSON in rig['sekiro_control_rig'] and the original action is in rig['sekiro_control_rig_action'].
- Sockets get a static pose inv(socket rest) @ game rest (_rest_on). Blender derives rest matrices through the parent (armature_finalize_restpose), and vec_roll_to_mat3 snaps a bone within 2.5e-4 rad of its parent's -Y axis onto it, so a copy under another parent can rest about 0.015° off (Sekiro face bones under face_root).
- FK controls: parent CTRL-Root for skeleton roots, the game parent itself when that is IK-driven and the bone is not (so it follows the blend), else FK-<parent>. Y points at the next joint by anatomy (centre chain, clavicle-arm, leg-toe, finger segments, hand to the middle finger base), else the heaviest child, else continues the parent; the head continues the neck; toes are flattened forward. Z hints: torso forward, clavicle and arms -forward, thigh and calf forward, foot, toe and fingers up. Size = hip height above the feet, else half the bounding diagonal. A bone whose sampled basis scale differs per axis by more than 1e-4 gets a control copied from the game bone (same axes): a turned control would need shear.
- IK per limb: MCH-IK-upper (parent FK-<upper's parent>, COPY_LOCATION from FK-upper), MCH-IK-lower connected with the IK constraint (target IK-<end>, pole Pole-<lower>, pole_angle -90°, chain 2, use_tail, no stretch), lock_ik_y/z, X limit [min(0, -bend), max(0, π - bend)], static pre-bend of max(0, 15° - bend) about X; MCH-IK-end connected with COPY_ROTATION from the IK control, which shares its rest. Hinge: the rest plane normal if the rest bend exceeds 1°, signed toward the measured or natural bend; else the axis the clip bends around, measured in the upper bone's frame; else u × natural (forward for arms, -forward for legs). Chain X = hinge; the elbow side is -Z.
- Bake: FK control world = M_game @ inv(R_game) @ R_ctrl; IK control = M_end @ inv(R_end) @ R_ik; pole at elbow + side × half the reach (geometric side when the bend sine exceeds 0.05, the rest side turned with the upper bone below 0.01, blended between). Bases come from convert_local_to_pose(invert=True); varying channels are keyed LINEAR, constant ones set once. The new action "<clip> Controls" is tagged sekiro_control_rig with sekiro_control_rig_base = original (fake user). Blender 4.4+ layered actions: slots, layers, strips, channelbag.
- Setting an ID property from Python does not tag the depsgraph, so switch() calls rig.update_tag(); UI edits of ID properties tag their owner in rna_property_update, so the slider updates live. add() turns on show_in_front, because most controls lie inside the mesh; removal restores the previous value.
- Exporter (standalone/blender_bridge.py): control_bones(); keyed_bones(action, rig) counts keyed controls for their game bones; drives_controls(). export_motion refuses an action that does not animate the controls of a rig with a control rig; inspect_scene lists only control actions; paired_root_action follows sekiro_control_rig_base. Retarget: bone_infos and rig_bones skip control bones, and bake refuses a target with a control rig.
- Panel SKR_PT_control_rig: per limb a labelled IK slider with Switch to IK / Switch to FK (match at every frame of the scene range or the current frame, then set the switch, keyed when the switch is animated), group toggles, and Remove (keep edits: "<clip> Edited" baked from the evaluated game bones; or restore the original). tools/package_addon.py includes control_rig.py.
- Tests: standalone/tests/blender_control_rig.py on owned fixtures. Probes on copies of the user's Sekiro scenes and UI screenshots stayed in the session scratchpad; results are in VERIFICATION.md.
- Open: no game playback of clips exported from a control rig; slider dragging by hand not exercised; no foot roll, finger IK, face controls or IK stretch; uneven scale on IK limb bones holds in FK only.
